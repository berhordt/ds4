## 1. Executive summary

The V4.1 attention/MoE graph in `ds4` was wired for **exactly two ranks**. This phase generalised it to the
fully‑connected N‑rank mesh transport and got V4.1‑Flash‑Q2 running at **world 4** on four M5 Max
128 GB machines with a TB5 RDMA clique.

Result on `http://Nemo.local:8140` (`deepseek-v4.1-flash`):

## 3. Bring‑up / operations reference

### Regenerate the topology after *any* reboot or cable change
Link‑local addresses change on every reboot, and swapping cables changes the port↔peer mapping.

```sh
# on Nemo
cd ~/github/berhordt/ds4-v4.1-tp4
python3 gen-mesh.py --hosts nemo,dory,fanny,gloria --port 9911
# then copy mesh.txt to the other three nodes
```

`gen-mesh.py` resolves each link to its peer (ARP‑MAC / ARP‑IP / ping) and writes the `world 4` +
`node R addr0 addr1 addr2` table. A 2‑node file (`--hosts nemo,dory`, e.g. `mesh2.txt`) is used for
world‑2 tests.

### Launch (world 4)
```sh
# Leader — Nemo
cd ~/github/berhordt/ds4-v4.1-tp4
AGX_RELAX_CDM_CTXSTORE_TIMEOUT=1 DS4_METAL_PREFILL_CHUNK=512 DS4_TP_TIMEOUT_SEC=20 \
  ./ds4-server --host 0.0.0.0 --port 8140 --ctx 4096 --role coordinator \
  --tp-topology mesh.txt --tp-rank 0 --transport rdma \
  --model gguf/DeepSeek-V4.1-Flash-Q2.gguf --tensor-parallel

# Workers — Dory / Fanny / Gloria (ranks 1 / 2 / 3)
AGX_RELAX_CDM_CTXSTORE_TIMEOUT=1 DS4_METAL_PREFILL_CHUNK=512 DS4_TP_TIMEOUT_SEC=20 \
  ./ds4 --tensor-parallel --role worker --tp-topology mesh.txt --tp-rank {1,2,3} \
  --transport rdma --model gguf/DeepSeek-V4.1-Flash-Q2.gguf --ctx 4096
```
- Start the **leader first**, wait until all three link listeners appear on port `9911`, then start workers.
- API: `POST http://Nemo.local:8140/v1/chat/completions`

### Environment variables used
| Variable | Why |
|---|---|
| `AGX_RELAX_CDM_CTXSTORE_TIMEOUT=1` | relaxes the Metal command‑buffer timeout while a rank waits at a TP gate |
| `DS4_METAL_PREFILL_CHUNK=512` | prefill chunk size used in these runs |
| `DS4_TP_TIMEOUT_SEC=20` | transport gate timeout (keeps failures fast/diagnosable) |
| `DS4_V41_PROBE=1` | **debug only** — per‑rank tensor hash probe (see §5) |
| `DS4_V41_PROBE_LAYERS=N` | limit probing to layers `0..N` (default `3`) |

### Operational gotchas (all hit during this phase)
1. **Regenerate `mesh.txt` after every reboot.**
2. **Re‑apply `sudo sysctl -w iogpu.wired_limit_mb=120000` after every reboot.**
3. **Node LAN IPs are DHCP and change**; the SSH mesh config must be refreshed, or use mDNS names.
4. **Disconnecting/reconnecting a TB cable (e.g. to shuttle a drive) can wedge the RDMA/TB state.**
   Symptom: a plain bound `connect()` succeeds, but `ds4` gets `EHOSTUNREACH` with no SYN.
   **Fix: reboot the affected nodes.** Cabling checks: `ibv_devices` shows 3 devices per node,
   `gen-mesh.py --verify` resolves 3 peers per node.
5. If a rank reports `Metal command batch failed: kIOGPUCommandBufferCallbackErrorTimeout`
   inside a TP gate, the peer is not participating in that gate (see §4).

## 4. What was broken at world 4 (and the fixes)

The starting point: at world 4 all four ranks connected over RDMA, then either failed immediately at
layer 0 (`V4.1 layer 0 failed at position 0` on ranks ≥ 2) or hung in a gate and produced a
GPU command‑buffer timeout.

### 4.1 Hard‑coded two‑rank graph — `ds4.c` (graph init)
```c
s->ds41_graph.tp_world = 2;          /* was hard-coded */
```
The graph believed it was always world 2. With `DS4_N_OUT_GROUP = 8` and `tp_world = 2`, ranks ≥ 2
computed attention‑A row offsets (`group0 * 1024` rows) *past the end of the tensor*, which is why
ranks 0/1 limped forward into the gate while ranks 2/3 died at layer 0.

**Fix:** take the real width and wire the transport views the V4 graph already uses:
```c
s->ds41_graph.tp_world    = (uint32_t)e->tp.world;
s->ds41_graph.tp_rank     = (uint32_t)e->tp.rank;
s->ds41_graph.tp_out      = e->tp.out_views;
s->ds41_graph.tp_in       = e->tp.in_views;
s->ds41_graph.tp_combined = e->tp.combined_views;   /* canonical sum for world>2 */
s->ds41_graph.tp_zero     = e->tp.zero_vec;
```
Also, the vocab‑split logits slice was derived from a hard half; it now uses
`ds4_tp_vocab_slice(DS4_N_VOCAB, world, rank, &off, &count)` (byte‑identical for world 2).

New fields added to `ds41_gpu_graph`: `tp_combined`, `tp_zero`, `tp_big_out`, `tp_big_in`
(the last two are the batch big‑gate bounce buffers, see §4.3).

### 4.2 Cross‑rank sums — `ds4.c`
**`ds41_sum_partial`** (the small per‑gate exchange used by the token path) was a no‑op for world ≠ 2
(`if (g->tp_world != 2) return true;`), so the routed‑MoE partials were never combined.

**Fix:** world 2 keeps the pairwise add via `tp_out`/`tp_in`; **world>2 reads the transport's
canonical rank‑order sum from the combined slot** (`tp_combined[slot]`), exactly like the V4 graph.

**`ds41_sum_partial_batch`** (the prefill big gate) likewise early‑returned for world ≠ 2 and its
world‑2 form only had a one‑row peer buffer (`g->batch.q`).

**Fix:** added a CPU‑visible bounce pair (`ds41_tp_big_bounce_ready`) sized
`rows*N_EMBD` out / `(world-1)*rows*N_EMBD` in. The local partial is staged into `tp_big_out`, the
mesh big gate runs, then:
- world 2: `x = tp_big_out + tp_big_in`
- world>2: `x = tp_big_in[0..bytes)` (the transport folded the canonical sum into the head of the
  in‑buffer — same convention as `glm_graph_tp_batch_ffn_combine`)

### 4.3 Gate‑slot ordering — `ds4.c`
The N‑rank transport requires **every gate slot to be fired in order**
(`tp_gate_slot(seq) == layer*DS4_TP_GATES_PER_LAYER + gate`). Simply skipping the attention gate at
world>2 produced:
```
ds4-tp: gate order broke: layer 0 gate 1 vs seq 1
```
**Fix:** `ds41_attention_gate()` still *exchanges* the ATTN gate at world>2 (copy to `tp_out[slot]` +
`ds4_gpu_tp_gate_encode`) but discards the result, keeping the transport's slot order valid.

### 4.4 Attention replication + the real culprit — `ds4.c`
Because V4.1's attention "TP" is a pair of decompositions (head split for the q/O projections, group
split for the output projection) that only line up neatly at world 2, world>2 now **replicates the
attention core** (every rank computes all heads) and the only cross‑rank couplings are the MoE sums:

- `ds41_attention_low`: groups / group0 split only for world 2.
- `ds41_attention_output`: k‑sliced output projection only for world 2.
- `ds41_attention_batch` / `ds41_attention`: `heads = N_HEAD` and `head0 = 0` for world>2.
- `ds41_tp_batch_enabled`: allow world>2.

**The decisive bug** was still hiding after all of the above — the hidden state was still wrong.
`ds41_attention_project` (and its `_batch` twin) rank‑slice the **q projection**:
```c
const uint32_t q_dim = DS4_N_HEAD / g->tp_world * DS4_N_HEAD_DIM;
ds41_matmul_rows(g->q, m, l->attn_q_b, g->qr, g->tp_rank * q_dim, q_dim);
```
At world 4 each rank filled only 32 heads of `q`, while replicated attention read all 128 → garbage
beyond the first 32 heads, on every rank.

**Fix (both functions):** project the full head range unless world 2:
```c
const bool head_split = g->tp_world == 2;
... head_split ? g->tp_rank * q_dim : 0u,
    head_split ? q_dim : DS4_N_HEAD * DS4_N_HEAD_DIM
```

### 4.5 `ds4_metal.m` — `ds4_gpu_dsv41_attention_output_tp_batch`
Was hard‑wired to two ranks (`tp_rank > 1 → 0`, `shard_bytes = 4*1024*row`, `low_offset = tp_rank*4096`).
Generalised to N using `g_tp_split_world` / `g_tp_split_rank`:
```c
world        = g_tp_split_world > 1 ? g_tp_split_world : 2;
out_group    = 8;                        /* DS4_N_OUT_GROUP */
groups       = out_group / world;
shard_bytes  = groups * 1024 * ((4096/32)*34);
... out_a_offset + tp_rank*shard_bytes, ..., groups, 5120, ..., 8192, tp_rank*groups*1024
```
Byte‑identical parameter set for world 2. (World>2 no longer calls it, since attention is replicated,
but it is now correct for any width.)

### 4.6 Debug aid — `ds41_tp_probe`
Env‑gated (`DS4_V41_PROBE`) per‑rank tensor hash/sum probe used to localise the fault; it is a no‑op
when the variable is unset. Keep or delete at leisure.

## 5. How the bug was found (methodology worth reusing)

With `DS4_V41_PROBE=1` (and `DS4_V41_PROBE_LAYERS=0`) the probe prints an FNV hash, sum and first two
values per rank at three points: `attn_out`, `attn_gated`, `routed_sum`.

World 2 — self‑consistent:
```
r0 attn_gated  il=1 fnv=9a3877760c74593f sum=-32.1014
r1 attn_gated  il=1 fnv=9a3877760c74593f sum=-32.1014
r0 routed_sum  il=0 fnv=3b4bdaa92256e5b6 sum=-0.704661
r1 routed_sum  il=0 fnv=3b4bdaa92256e5b6 sum=-0.704661
```

World 4 — **before** the q‑projection fix:
```
r0 attn_out il=0 fnv=481b00d2089a1f19 sum=-50.3228
r1 attn_out il=0 fnv=e14f1c8b1ae46220 sum=-14.3446    <- divergent!
r2 attn_out il=0 fnv=ab13c35d8008accf sum=-45.6587
r3 attn_out il=0 fnv=6251ef70f5c2b8a1 sum=-25.4513
r0..r3 routed_sum il=0 fnv=b2a1256453aef2b2          <- matching (MoE sum already correct)
```

World 4 — **after**:
```
r0..r3 attn_out  fnv=7ab30b88ff2b5040 sum=58.3119    (and identical for every token/layer)
r0..r3 routed_sum fnv=7634e3f0d5b1f383
```

Two useful lessons:
1. Because *both* prefill paths (batched and token‑at‑a‑time) produced **byte‑identical** garbage, the
   fault had to be in a component shared by both — which is what pointed at the attention projection
   rather than the batch/row plumbing.
2. Probing `routed_sum` and `attn_out` separately immediately separated "the MoE exchange is fine"
   from "the attention is not replicated after all".

## 8. Known issues / next steps

1. **Perf: attention is replicated at world>2** (every rank computes all 128 heads and the whole
   output projection). Correct but ~4× the attention work. The plumbing for a proper N‑way split is
   now in place — `ds4_gpu_dsv41_attention_output_tp_batch` is N‑general and the N‑way attention sum
   works — so the head/group split can be re‑enabled with a rank‑sliced q projection and the ATTN gate
   restored to a real sum. Expected to close part of the gap to V4‑Flash's ~56 t/s.
2. **Decode throughput** at world 4 is ~26 t/s vs ~56 t/s for V4‑Flash MXFP4; V4.1‑Q2 is a larger,
   deeper model, but a profile pass (and item 1) is worthwhile.
3. `DS4_METAL_DISABLE_V41_TP_SHARED_OWNER` semantics are world‑2‑specific by design; at world>2 the
   shared expert is computed whole on every rank and folded in by the caller — confirmed correct, but
   it is extra per‑rank work that could be split later.
4. The `ds41_tp_probe` debug hook is left in (env‑gated, zero cost when off); remove before any
   upstream‑facing work.
5. Nothing in this phase was pushed upstream; the branch exists only locally on the nodes.
